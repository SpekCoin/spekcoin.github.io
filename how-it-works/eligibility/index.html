How it works

Eligibility

Since every draw counts the same, the cost of fielding a draw is where the security lives. Spek prices it in two phases, and in both the thing that makes a key eligible must be on chain before the beacon it competes against.

The seed phase: ticket records

At launch nobody holds coins, so a coin requirement would be zero and a draw would cost one key generation. The first 45 days (129,600 blocks) therefore use a different price: a RandomX ticket per round. The seed phase has 15 rounds of 8,640 blocks, 3 days each.

A ticket is a nonce for which a RandomX hash over the round, the round's seed, the miner's stake program and the nonce falls below a fixed target. The stake program is the 32-byte hidden-key program of the miner's stake address, so a ticket belongs to one key. A ticket counts only once it is recorded on chain: a 48-byte record carried in a seed-phase coinbase, at most 16 per block and one per stake program per round. Records travel on their own gossip topic, and every block producer includes pending ones.

A record may be for the current or the next round, and it counts only for the heights after its stake cutoff, which is 24 to 36 hours after it lands on chain. A ticket found during a round therefore works, but only for the rest of that round after the cutoff. To cover a whole round, the record must land about two epochs before the round starts, which leaves a 48-hour search window per round. Finding it later costs only the part of the round already gone. Because the ticket is committed before the beacon it competes against exists, nobody can rank free keys by their scores in a known epoch and buy tickets only for the best ones.

What "about 3 tickets per round" means for a home machine

The target was calibrated so that a 2018-era 8-core desktop running the search in its spare cycles finds about three tickets per round. One recorded ticket per round is all a key needs, so an ordinary computer can keep one key eligible, with room for an unlucky round. A round in which nobody is eligible is covered by the null block.

Searching uses RandomX's dataset of about 2 GiB; checking a ticket uses light mode, a 256 MiB cache and 15–30 ms. The RandomX instance is a Spek variant with its own parameters, so rented hash power built for other chains cannot be pointed at it.

The effect is that seed-phase draws are priced by sustained work per round rather than by a one-time key generation: a bank of keys is worthless without fresh work per key per round.

The open launch: the first 36 hours

Epochs 0–2, the first 36 hours, count only records written into the genesis block, and anyone can win one.

  1. The search opens at a pre-announced Bitcoin block. Its hash, with the network name, gives the launch key, so no ticket can exist before it.
  2. Anyone searches for a round-0 ticket under the launch key, at the same target, and submits the record to a public submission channel. The channel checks each ticket on arrival and lists every valid entry with its ticket hash, so anyone can recheck the listing.
  3. After the deadline the list is sealed: it is published with the genesis timestamp (6 hours after the deadline), the genesis message and the allocation, a digest over all of them, and the height of a Bitcoin block six blocks past the tip at that moment. Independent witnesses (anyone may witness) record the digest before that block is mined.
  4. The genesis block takes up to 1,973 records, one per key, chosen by lowest ticket hash, so when more are submitted than fit, searching longer buys better odds.
  5. The launch nonce is derived from the launch key, the seal digest and that Bitcoin block's hash, and the genesis builder is deterministic. The launch beacons depend on a value nobody knew while any input could still change, and anyone can recompute the selection and the genesis block from public inputs.

One record is one key, and a node mines one key, so a launch seat costs what every later round costs: one ticket.

After the seed phase: one stake output

From block 129,600 a key is eligible at height h when its stake address holds one unspent output that

  • is worth at least the coin requirement, max(80% of the block reward, 0.1 coin): several smaller outputs do not add up;
  • was created below the stake cutoff, one full epoch below the beacon height, so new stake first counts 24–36 hours after it is created;
  • if it is a coinbase output, is mature (3,000 blocks).

The stake address is a hidden-key address built from the miner's key and the commitment to its slot secrets. Nothing is locked: the output is an ordinary coin. Eligibility is judged against the parent block's ledger, so spending the output ends eligibility from the next block. Each funded stake address and horizon is one draw per slot, not each key. A stake address is built from the key and one horizon's commitment, so it belongs to exactly one horizon, and each horizon has its own address and its own output. A key with two funded horizons holds two draws: its miner computes both scores and publishes only the better header, so the network sees one header. Each of those outputs must hold a full requirement of its own, so two draws cost twice the capital, exactly as two keys would. One output counts for one address only, and moving coins between addresses restarts their aging. A block cannot create draws for its miner: it pays one block reward, which funds at most one more output.

The requirement halves with the reward. The 0.1-coin floor only binds about nine halvings, roughly 36 years, out.

Why 80%

The requirement sets the size of one draw, not the cost of an attack. Matching the honest network costs roughly the capital it holds, whatever the price of a single draw. After the seed phase, block production is capital-proportional: a holder of X coins can fund ⌊X/requirement⌋ stake outputs and wins slots in that proportion.

Horizons and renewal

A stake output commits to one horizon: the slot secrets for 1,024 segments of 3 days, about 8.4 years. A node creates its next horizon automatically about a year before the current one ends (122 segments by default, an operator setting), with two segments of overlap so eligibility never lapses.

Renewal is an ordinary transaction, and no block win is needed. The node builds the next horizon in 1 to 3 seconds and the next horizon's address needs one output of at least a requirement, which can come from three places: the coinbase of a block the miner wins, surplus at the current address that the node sends itself, or a transfer from a wallet. A miner holding exactly one requirement and never winning needs the wallet transfer. Nothing is locked, so once the new output has aged the old one can be spent, and the capital is doubled only for that aging period and the overlap. The node warns ten segments before a horizon ends if the next one is not funded.

The stake key is public in every header and lives on the mining machine, so the node keeps exposure to one stake unit. The coinbase pays the stake address of the first horizon not yet funded, then a separate hidden-key payout address. A winner therefore funds its next horizon for free; a key that never wins renews with one ordinary transaction, which the node makes itself from any surplus at the current stake address, or which the operator funds from a wallet. The node also merges a stake address funded in pieces into a single output.

After the seed phase

Ticket holders must fund a stake output below the cutoff of the first epoch after the seed phase. The node warns seven days ahead.

What taking part costs

  • no ASIC race;
  • no lock-up or slashing;
  • an ordinary computer is enough (the published minimum is 4 dedicated cores, 8 GB of RAM and an SSD);
  • one funded stake output keeps a key eligible for its whole 8.4-year horizon;
  • each stake unit gets exactly one draw per slot.
