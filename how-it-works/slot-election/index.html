How it works

Slot election

Every 30 seconds the network elects one block. Each eligible stake output gets exactly one draw, and no one, the owner included, can rank keys for a future slot before its beacon is fixed. The beacon is a random value, fixed a full epoch ahead, that every draw is scored against. No one else can know a miner's score until its header is published. Terms are collected in the glossary.

Spek calls a block producer a miner, the word the protocol and its software use. Mining here means submitting one candidate block per slot, not racing to find a hash.

One draw

A miner's score for the slot at height h is

score = middle_out( BLAKE3("spek/score/v2" ‖ B_e ‖ h ‖ pk ‖ r_h) )
  • B_e is the beacon for the epoch the slot belongs to (an epoch is 1,440 slots, 12 hours);
  • h is the height, which is also the slot number;
  • pk is the miner's public key;
  • r_h is the miner's slot secret for that height: a value only the key owner can compute, unique per height, committed inside the stake output before the beacon existed.

middle_out measures how far the hash, read as a 256-bit number, sits from the centre of the hash space. Both 0x00…00 and 0xFF…FF score the maximum, 2255; the two values either side of the centre score 1. The highest score whose full block validates wins the slot.

Every input is fixed before the beacon it is drawn against exists, and the key sits inside the hash, so there is nothing to grind: no nonce, no key to swap in afterwards, and nothing a winner can re-sign or re-order to improve its own or any later draw.

Copying does not help either. The key is part of what is hashed, so if someone copies another miner's commitment, or reuses a slot secret the other miner already published, the hash they get is different from the original owner's, because it contains their own key. They have a draw of their own, not the owner's score. A copied commitment also cannot be used to build a valid header, because the stake address it opens is the owner's, and only the owner holds the seed that produces its slot secrets.

Slot secrets

Each miner key file holds a SQIsign Level I key pair and a 32-byte slot seed, the secret every slot secret is derived from, drawn from the operating system's random source, independent of the signing key. From the slot seed the node builds one hash chain per 3-day segment and reveals it backwards, one value per slot, so publishing a slot's secret exposes only values for heights already passed. The tops of 1,024 consecutive segment chains, about 8.4 years, form a Merkle tree whose root is committed in the stake output. That commitment is made before any beacon it will be drawn against exists, so for every key, commitment and height exactly one slot secret verifies.

A header carries the slot secret and its Merkle path. A verifier walks the secret up to its segment top, climbs the path, and uses the root it derives to rebuild the stake address. If the secret is wrong, there is simply no stake at that address.

The beacon

The beacon for epoch e is read from the chain's election seed at the last block of epoch e−2, a full epoch before epoch e starts. Every block mixes its winner's slot secret into the election seed, so the beacon cannot be predicted until that whole source epoch has been produced. It is the same on every fork that shares that history, which covers every propagation fork.

Stake counts only if it was created below a cutoff one full epoch before the beacon height. Anyone who learns a beacon is already too late to create a key, fund it and have it count for that beacon's epoch: new stake first counts 24–36 hours after it is created.

What was measured and accepted

The miner at a beacon height can withhold its block and let the runner-up set the beacon instead, and because it holds its own future slot secrets it can evaluate both choices. Simulation puts the gain at 1.9–3.0% more of its own wins per beacon it controls, 0.3–0.6% averaged over all epochs, with no compounding.

Why share equals draws

Each draw is an independent random number, and the winner is the highest. Take one party holding N draws and everyone else holding H in total. Before the scores are known, every one of the N+H draws is equally likely to be the highest, since none is favoured. So the chance that the highest is one of the party's N is N out of N+H, which is the party's share of the draws and nothing more: not more because it is rich, not less because it is small. No election rule can change that, so what a draw costs to field is where the security lives. Spek prices it explicitly: see Eligibility. Because no winner schedule exists to read in advance, there is no predicted winner to attack or bribe.

Inside one slot

For the first 6 seconds only headers travel: 743-byte candidate headers flood the network and the ranking settles. From 6 to 30 seconds nodes pull full bodies only for the top three candidates and serve the top five. At the slot boundary each node commits the highest-ranked candidate whose full body is in hand and passes validation. If none does, every node builds the same null block.

A miner key gets one entry per slot. A second header from the same key with different signed content is equivocation: the key's entry is evicted for that slot, and a compact proof is passed on so every node does the same.

Add miners, each with a stake output and its own slot seed (the secret that its slot secrets come from, described under Slot secrets above), then advance slots: each score appears only when its header is published, and the highest score wins.
